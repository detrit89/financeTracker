# Finance Tracker

Учебное full-stack приложение для учёта личных доходов и расходов. Позволяет добавлять операции, следить за балансом и находить нужные записи в истории.

## Статус проекта

Проект находится в активной разработке. Тестовая версия поддерживает десктоп, планшеты и телефоны.

**Добавлена адаптивная вёрстка для телефонов и планшетов:** навигация переносится на отдельную строку, карточки и форма перестраиваются под ширину экрана. Таблица операций прокручивается горизонтально внутри своего блока.

Тестовая версия размещена на Vercel и Render:

- [Открыть приложение — Vercel](https://finance-tracker-smoky-mu.vercel.app/)
- [API операций — Render](https://financetracker-iwt9.onrender.com/api/transactions)

Фронтенд обращается к API на Render. В исходниках бэкенда CORS настроен на домен приложения Vercel; изменения этой настройки вступают в силу после повторного деплоя бэкенда.

## Возможности

- **Overview** — баланс, общие доходы и расходы, пять последних добавленных операций.
- **Transactions** — история операций, поиск по описанию и типу, фильтрация доходов и расходов.
- Добавление операций с описанием, суммой, типом и датой.
- Редактирование описания, суммы и даты операции.
- Удаление операций.
- Очистка формы после успешного добавления.
- Хранение данных в SQLite.
- **Settings** — страница-заготовка для будущих настроек.

## Локальный запуск

### Требования

- Node.js 22.12+ или совместимая с Vite версия.
- npm.
- Bun.
- Современный браузер с поддержкой `Array.prototype.toSorted`.

### Установка зависимостей

Из корня проекта:

```sh
npm ci
cd front
npm ci
cd ../backend
bun install
```

Установка в корне нужна, поскольку Tailwind CSS и его Vite-плагин сейчас объявлены в корневом `package.json`.

### Бэкенд

В первом терминале, из корня проекта:

```sh
cd backend/src
mkdir -p data
bun server.js
```

По умолчанию API доступен на `http://localhost:3000`.

В текущей реализации путь `data/finance.sqlite` считается относительно рабочей папки. Запуск из `backend/src` использует `backend/src/data/finance.sqlite`. При первом запуске таблица создаётся автоматически.

### Фронтенд

Во втором терминале, из корня проекта:

```sh
cd front
npm run dev -- --port 5173 --strictPort
```

Откройте `http://localhost:5173`.

По умолчанию исходники фронтенда обращаются к опубликованному API:

```text
https://financetracker-iwt9.onrender.com/api/transactions
```

Для полностью локальной разработки измените `BASE_URL` в `front/src/api/transaction.js` на `http://localhost:3000/api/transactions`, а `Access-Control-Allow-Origin` в `backend/src/server.js` — на `http://localhost:5173`. Перезапустите локальный бэкенд. Перед публикацией верните адрес API Render и origin Vercel.

Текущая CORS-конфигурация разрешает только origin `https://finance-tracker-smoky-mu.vercel.app` — без завершающего `/`. Запросы с localhost к опубликованному API этой конфигурацией не разрешены.

## Команды фронтенда

Выполняются из папки `front`:

```sh
npm run dev          # режим разработки
npm run lint         # проверка ESLint
npm run build        # сборка в dist
npm run preview      # локальный просмотр сборки
```

Для работы API через preview нужно отдельно разрешить его origin в CORS; стандартный адрес preview — `http://localhost:4173`.

## API

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/api/transactions` | Получить все операции |
| GET | `/api/transactions/:id` | Получить одну операцию |
| POST | `/api/transactions` | Добавить операцию |
| PATCH | `/api/transactions/:id` | Изменить операцию |
| DELETE | `/api/transactions/:id` | Удалить операцию |

Пример тела POST-запроса с заголовком `Content-Type: application/json`:

```json
{
  "type": "expense",
  "amount": 25000,
  "description": "покупка машины",
  "transaction_date": "2026-10-29"
}
```

- `type` — `income` или `expense`.
- `amount` — положительное целое число. Дробные суммы пока не поддерживаются.
- `description` — непустое описание.
- `transaction_date` — дата операции; интерфейс передаёт её в формате `YYYY-MM-DD`.

PATCH принимает изменяемые поля. Успешное создание возвращает статус 201, изменение и удаление — 200, тело ответа — `{"success":true}`.

## Размещение на серверах

Фронтенд размещён на **Vercel**, бэкенд — на **Render**.

| Назначение | Адрес |
| --- | --- |
| Приложение | https://finance-tracker-smoky-mu.vercel.app/ |
| Бэкенд | https://financetracker-iwt9.onrender.com |
| API операций | https://financetracker-iwt9.onrender.com/api/transactions |

При обновлении опубликованной версии:

1. Отправьте изменения в подключённый GitHub-репозиторий и проверьте успешное завершение деплоев Vercel и Render.
2. После изменения CORS повторно разверните бэкенд: настройки в локальном файле не меняют уже запущенный сервер.
3. При смене доменов обновите адрес API во фронтенде и разрешённый origin на бэкенде.
4. Для клиентских маршрутов `/transactions` и `/settings` настройте возврат `index.html`, чтобы прямое открытие и обновление страницы работали.
5. Используйте постоянное хранилище для SQLite: файл базы должен сохраняться между перезапусками и обновлениями сервера. Текущий относительный путь `data/finance.sqlite` нужно согласовать с расположением этого хранилища.
6. После деплоя проверьте загрузку изображений, получение списка, создание, редактирование и удаление операций.
