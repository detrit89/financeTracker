# Finance Tracker

Учебное full-stack приложение для учёта доходов и расходов на React и JavaScript. Можно добавлять финансовые операции, редактировать их, искать записи и следить за общим балансом. Данные хранятся в SQLite и доступны через HTTP API на Bun.

Мой первый pet-проект для практики React, работы с API и разработки приложения от интерфейса до базы данных.

[Открыть демоверсию](https://finance-tracker-smoky-mu.vercel.app/)

## Возможности

- **Overview (`/`)** — баланс, суммарные доходы и расходы, форма создания и пять последних добавленных операций.
- **Transactions (`/transactions`)** — список операций, поиск по описанию и типу без учёта регистра, фильтр Income / Expense.
- **Settings (`/settings`)** — переключение светлой и тёмной темы. Выбор сохраняется в `localStorage`.
- Создание операции с описанием, суммой, типом и датой.
- Редактирование описания, суммы и даты; удаление операций.
- Обновление списка и сводных сумм после успешных CRUD-операций.
- Адаптивная вёрстка; на небольших экранах таблица прокручивается горизонтально.
- Индикатор загрузки списка, сообщение об ошибке его получения и блокировка кнопки добавления на время отправки.

Сводные суммы рассчитываются по всем операциям и не меняются при поиске или фильтрации. Последние операции на Overview выбираются по убыванию ID, а не по указанной пользователем дате.

## Локальный запуск

Понадобятся Node.js, npm, Bun и современный браузер с поддержкой `Array.prototype.toSorted`. Для frontend можно использовать Node.js 24 LTS. Backend использует встроенные возможности Bun, поэтому запускать его через Node.js нельзя.

Команды ниже выполняются из корня клонированного проекта, если не указано другое.

### 1. Установить зависимости

```sh
npm ci
npm ci --prefix front
cd backend
bun install
```

Зависимости устанавливаются и в корне: там объявлен `tailwindcss`, который импортируется в CSS frontend.

### 2. Настроить локальное соединение

Сейчас адрес API и разрешённый origin заданы непосредственно в исходниках. `.env` для этих настроек пока не подключён.

В `front/src/api/transaction.js` замените значение `BASE_URL`:

```js
const BASE_URL = 'http://localhost:3000/api/transactions';
```

В `backend/src/server.js` замените значение `Access-Control-Allow-Origin`:

```js
"Access-Control-Allow-Origin": "http://localhost:5173",
```

В исходной конфигурации frontend обращается к API на Render, а backend разрешает браузерные запросы только с домена демоверсии Vercel. Без этих двух изменений полностью локальный запуск не будет работать корректно.

### 3. Запустить backend

В первом терминале из корня проекта:

```sh
cd backend
PORT=3000 bun src/server.js
```

API будет доступен по адресу `http://localhost:3000/api/transactions`.

При таком запуске база создаётся в `backend/data/finance.sqlite`. Папка `data` и таблица создаются автоматически. Путь базы считается относительно рабочей директории процесса: если запускать сервер из другой папки, будет использован другой файл SQLite.

### 4. Запустить frontend

Во втором терминале из корня проекта:

```sh
cd front
npm run dev -- --port 5173 --strictPort
```

Откройте [http://localhost:5173](http://localhost:5173).

При изменении CORS перезапускайте backend. Для публикации используйте адрес и origin нужного окружения.

## API

Базовый путь — `/api/transactions`. Тела POST и PATCH передаются в JSON с заголовком `Content-Type: application/json`.

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/api/transactions` | Массив операций |
| GET | `/api/transactions/:id` | Одна операция |
| POST | `/api/transactions` | Создание, статус `201` |
| PATCH | `/api/transactions/:id` | Частичное обновление, статус `200` |
| DELETE | `/api/transactions/:id` | Удаление, статус `200` |

Пример тела POST:

```json
{
  "type": "expense",
  "amount": 250,
  "description": "Продукты",
  "transaction_date": "2026-11-01"
}
```

| Поле | Формат |
| --- | --- |
| `type` | `income` или `expense` |
| `amount` | Положительное целое число; дробные суммы не поддерживаются |
| `description` | Строка, содержащая хотя бы один непробельный символ |
| `transaction_date` | Непустая строка; интерфейс передаёт дату в формате `YYYY-MM-DD` |

Сервер добавляет `id` и `created_at`. Успешные POST, PATCH и DELETE возвращают `{"success":true}`. PATCH поддерживает поля из примера выше; интерфейс редактирования меняет только описание, сумму и дату. Проверка календарной корректности даты на сервере пока не реализована.

## Публикация

Адреса демоверсии, указанные в проекте:

- Frontend на Vercel: [Finance Tracker](https://finance-tracker-smoky-mu.vercel.app/).
- Backend на Render: [API операций](https://financetracker-iwt9.onrender.com/api/transactions).

Для собственного развёртывания:

1. Установите зависимости корня и `front`, соберите frontend командой `npm run build` из `front`. Публикуйте `front/dist`.
2. Настройте возврат `index.html` для клиентских маршрутов, включая `/transactions` и `/settings`.
3. Запускайте backend через Bun; согласуйте рабочую директорию и путь `data/finance.sqlite` с постоянным диском хостинга.
4. Укажите нужный `BASE_URL` во frontend и точный origin frontend в CORS backend — без завершающего `/`.

## Текущие ограничения и дальнейшая работа

Проект развивается как учебное приложение. Регистрация, авторизация и разделение операций по пользователям пока не реализованы.

Ближайшие задачи:

- Показывать пользователю ошибки создания, редактирования и удаления.
- Блокировать повторные Save и Delete во время запроса.
- Сохранять черновики форм при обновлении списка.
- Добавить защиту от устаревших ответов API и повторную загрузку после ошибки.
- Вынести адрес API и CORS-настройки в конфигурацию окружений.
- Согласовать поддержку дробных денежных сумм и расширить валидацию.
- Добавить тесты CRUD-сценариев и ошибок сети.
